# Contributing to Verborra

Thank you for your interest in Verborra. Contributions are released to the
public under the project's [MIT License](LICENSE).

By participating, you agree to abide by the [Code of Conduct](CODE_OF_CONDUCT.md).

> [!NOTE]
> For non-trivial changes (new features, architectural changes, anything
> touching the recording or formatting pipeline), please **open an issue
> first** to discuss scope. PRs with large unexpected changes may be closed
> without review.

---

## Quick start

Prerequisites:

- macOS 15 (Sequoia) or newer
- Xcode 16+
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) — `brew install xcodegen`
- An [OpenAI API key](https://platform.openai.com/api-keys) for runtime testing

```bash
git clone https://github.com/dbknv/verborra.git
cd verborra
xcodegen generate
open Verborra.xcodeproj
```

Build & run in Xcode (`⌘R`).

## Running the tests

```bash
xcodebuild test -project Verborra.xcodeproj -scheme Verborra -destination 'platform=macOS'
```

The full test suite must be green before opening a PR.

## PR workflow

1. **Discuss first for non-trivial changes** — open an issue describing the
   change before writing code.
2. Fork and clone the repository.
3. Create a feature branch from `main`: `git checkout -b feature/my-change`.
4. Make your changes — keep them focused (one feature or fix per PR).
5. Run the test suite locally; ensure it is green.
6. If the change affects UI behavior, manually test the affected flow
   (record → transcribe → format → paste).
7. Open a PR with a clear description of the change and motivation.

## Project layout

```
Verborra/
├── Verborra/              # App sources
│   ├── Models/            # Data models, settings, vocabularies
│   ├── Views/             # SwiftUI views (Settings, Overlay)
│   ├── ViewModels/        # ObservableObject state holders
│   ├── Services/          # OpenAI client, audio capture, hotkeys, logging
│   └── Resources/         # Assets, localizations, entitlements
├── VerborraTests/         # Unit tests
├── Verborra.xcodeproj/    # Generated by XcodeGen — do not edit by hand
├── Package.swift          # SwiftPM manifest (tooling)
├── project.yml            # XcodeGen spec — edit this, then re-run xcodegen
└── specs/                 # Per-feature design specs (internal reference)
```

If you regenerate the Xcode project, **never commit changes to
`Verborra.xcodeproj/` manually** — always edit `project.yml` and run
`xcodegen generate`.

## Code style

- **Swift**: follow standard SwiftUI / Swift conventions; use `final class`
  by default; prefer value types where reasonable.
- **Concurrency**: use `async/await` for new code; avoid mixing GCD and
  Swift Concurrency in the same path.
- **Logging**: use `os.Logger` for runtime logs and the project's
  `FlowTracker` for cross-event correlation.
- **Permissions**: never request a permission implicitly — all permission
  prompts go through the Settings UI.
- **Localization**: any user-facing string must go through `Localizable.xcstrings`.
- **Tests**: cover non-trivial logic in `VerborraTests/`. UI flows that are
  hard to unit-test should be documented in the PR description with a
  manual-test checklist.

## AI assistance disclosure

> [!IMPORTANT]
> If you are using **any kind of AI assistance** (Claude, Copilot, ChatGPT,
> agents, etc.) to contribute, this must be disclosed in the pull request.

AI-assisted contributions are welcome, but disclosure is required, along
with the extent of AI involvement (e.g., documentation comments vs. full
code generation).

**Exception:** trivial spacing or typo fixes don't need disclosure.

### What we expect from AI-assisted contributions

- **Clear disclosure** of AI use and degree.
- **Human understanding and testing** — you've personally validated the
  changes by running the app.
- **Clear rationale** — you can explain why the change is needed.
- **Concrete evidence** — test output, screenshots, or examples
  demonstrating the change works.

### What we'll close

- Untested changes submitted without verification.
- Generic AI-generated suggestions that don't address specific Verborra needs.
- Bulk submissions that show no human review.

## Releases

Releases are tagged `v<MAJOR>.<MINOR>.<PATCH>` per [SemVer](https://semver.org/).

Breaking changes to user-visible behavior, configuration formats, or
on-disk file layouts (`prompts.json`, `vocabularies.json`) → MAJOR bump.

See [CHANGELOG.md](CHANGELOG.md) for the release history.
